# Update Log — April 2026

## Overview

This document describes all the changes made in the `fix/update-and-improvement` branch for the Wapichana Dictionary web application (React frontend + AWS CDK serverless backend).

---

## 1. Frontend Library Updates

### React 16 → 18
- **Package**: `react@18.3.1`, `react-dom@18.3.1`, `@types/react@18.3.11`, `@types/react-dom@18.3.1`
- **Adaptation** (`src/index.tsx`): Replaced the deprecated `ReactDOM.render()` with the new React 18 `createRoot` API:
  ```tsx
  const root = createRoot(document.getElementById('root') as HTMLElement);
  root.render(<App />);
  ```
  This enables React 18 concurrent features and removes the deprecation warning.

### Material-UI v4 → MUI v5
- **Packages removed**: `@material-ui/core`, `@material-ui/icons`
- **Packages added**: `@mui/material@5.x`, `@mui/icons-material@5.x`, `@mui/styles@5.x`, `@emotion/react@11.x`, `@emotion/styled@11.x`
- **Adaptations**:
  - All imports changed from `@material-ui/core` → `@mui/material` and `@material-ui/icons` → `@mui/icons-material`.
  - `createMuiTheme` (deprecated) → `createTheme` from `@mui/material` in `App.tsx`.
  - `makeStyles` now imported from `@mui/styles` (MUI's legacy compatibility package) to minimize code churn while preserving the existing JSS-based styles.
  - `@mui/styles` requires `@emotion/react` and `@emotion/styled` as peer dependencies.

### React Router v5 → v6
- **Package**: `react-router-dom@6.26.2` (types are now bundled, removed `@types/react-router-dom`)
- **Adaptations** across `Main.tsx`, `WordList.tsx`, `Word.tsx`, `WordEditor.tsx`:
  - `<Switch>` → `<Routes>`
  - `<Redirect to="...">` → `<Navigate to="..." />`
  - `<Route exact path="/" component={...}>` → `<Route path="/" element={<Component />} />`  (the `exact` prop is no longer needed; all routes are exact by default in v6)
  - `useHistory()` → `useNavigate()` (returns a function directly, so `history.push('/path')` becomes `navigate('/path')`)
  - `ProtectedRoute` refactored: in v6, a wrapper component can't render a `<Route>` itself; instead it renders the children or a redirect directly, and is used inside `element={...}` prop.

### AWS Amplify v3 → v6
- **Package**: `aws-amplify@6.6.3`
- **Adaptations** (`src/api/auth.ts`, `src/components/Authenticator.tsx`):
  - New configure call uses `Auth.Cognito` namespace:
    ```ts
    Amplify.configure({ Auth: { Cognito: { userPoolId, userPoolClientId } } });
    ```
  - Auth functions now imported individually from `aws-amplify/auth`:
    - `Auth.signIn(u, p)` → `signIn({ username, password })`
    - `Auth.signOut()` → `signOut()`
    - `Auth.currentAuthenticatedUser()` → `getCurrentUser()`
    - `Auth.currentSession()` → `fetchAuthSession()`; tokens accessed via `session.tokens?.idToken`
    - `Auth.completeNewPassword(user, pw)` → `confirmSignIn({ challengeResponse: pw })`
    - `Auth.forgotPassword(u)` → `resetPassword({ username })`
    - `Auth.forgotPasswordSubmit(u, code, pw)` → `confirmResetPassword({ username, confirmationCode, newPassword })`
  - The `region` config option is no longer needed in Cognito-only setups.
  - In `Authenticator.tsx`, the `currentUser` state (holding the Amplify user object) is removed — `confirmSignIn` no longer needs it, as it uses the in-progress sign-in session automatically.

### Axios 0.21 → 1.13.5
- **Package**: `axios@1.13.5` (patched for SSRF/credential leakage CVE and DoS CVEs present in earlier 1.x versions)
- **Adaptation** (`src/api/auth.ts`): The interceptor config type changed from `AxiosRequestConfig` to `InternalAxiosRequestConfig`, and header assignment now uses the `set()` method:
  ```ts
  request.headers.set('Authorization', `Bearer ${token}`);
  ```

### React Toastify v6 → v10
- **Package**: `react-toastify@10.0.6`
- No code changes required — the `toast.success()`, `toast.error()`, `toast.warn()` APIs and `<ToastContainer />` component are backward-compatible.

### TypeScript 4 → 5
- **Package**: `typescript@5.6.3`
- No code changes required. TypeScript 5 is backward-compatible for this codebase.

### React Scripts 3 → 5
- **Package**: `react-scripts@5.0.1`
- No code changes required. CRA 5 supports React 18 and TypeScript 5 out of the box.

### React Redux v7 → v8 / Redux v4.2

## 2. Backend Updates

### Lambda Runtime: Node.js 16 → 20
- **Files**: `backend/lib/dictionary-fn-stack.ts`, `backend/lib/api-stack.ts`
- Changed `Runtime.NODEJS_16_X` → `Runtime.NODEJS_20_X` for all three Lambda functions (`wapichana-dictionary-function`, `wapichana-fileupload-function`, `wapichana-dictionary-authorizer`).
- **Why**: Node.js 16 reached end-of-life in September 2023 and AWS is deprecating NODEJS_16_X runtime. Node.js 20 is the current LTS version supported by AWS Lambda.

### AWS SDK v2 → v3 (Lambda functions)
- **Affected lambdas**: `wapichana-dictionary`, `file-upload`
- **Why**: `aws-sdk` (v2) is deprecated by AWS and will reach end-of-life. The modular `@aws-sdk` v3 packages are smaller (tree-shakeable), faster cold starts, and actively maintained.

#### `wapichana-dictionary` lambda:
- Replaced `require('aws-sdk')` with `@aws-sdk/client-dynamodb` and `@aws-sdk/lib-dynamodb`.
- DynamoDB operations now use the `DocumentClient` pattern from `@aws-sdk/lib-dynamodb` with the `send()` method and command objects (`ScanCommand`, `QueryCommand`, `GetCommand`, `PutCommand`, `UpdateCommand`, `DeleteCommand`).
- Added `@aws-sdk/client-dynamodb` and `@aws-sdk/lib-dynamodb` to the lambda's `package.json`.

#### `file-upload` lambda:
- Replaced `require('aws-sdk')` with `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner`.
- Pre-signed URL generation updated from `s3.getSignedUrl("putObject", params)` to:
  ```js
  const command = new PutObjectCommand(params);
  const url = await getSignedUrl(s3, command, { expiresIn: 120 });
  ```
- Added `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner` to the lambda's `package.json`.

### jwt-decode v3 → v4 (Authorizer lambda)
- **File**: `backend/lambda/authorizer/index.js`
- jwt-decode v4 changed to named exports: `import jwt_decode from 'jwt-decode'` → `import { jwtDecode } from 'jwt-decode'`.
- Updated `backend/lambda/authorizer/package.json` to `jwt-decode@^4.0.0`.

## 3. Bug Fixes

### Operator Precedence Bug in Lambda Handler
- **File**: `backend/lambda/wapichana-dictionary/index.js`
- **Before**: `if (method === 'GET' && path === '' || path === '/')` — due to operator precedence, `path === '/'` was always evaluated independently, causing all requests to match.
- **After**: `if (method === 'GET' && (path === '' || path === '/'))` — the OR condition is now correctly grouped.
- The same fix was applied to the POST handler.

### Wrong Argument in `updateEntry`
- **File**: `backend/lambda/wapichana-dictionary/index.js`
- **Before**: `return updateEntry(event.pathParameters.entry_id)` — passed only the ID string to a function expecting a full entry object with `entry_id`, `entry`, and `definition` fields.
- **After**: `return updateEntry(JSON.parse(event.body))` — correctly parses the request body as the entry to update.

### Improved Error Responses in Lambda
- All DynamoDB/S3 error responses now return proper HTTP `statusCode: 500` with a JSON body `{ error: message }` instead of returning a stringified error at an unexpected level. This makes error handling consistent and client-friendly.

### Typo Fix in Authorizer Context
- **File**: `backend/lambda/authorizer/index.js`
- Fixed `"boleanKey"` → `"booleanKey"` in the policy context object.

## 4. DynamoDB Improvements

### Billing Mode: PROVISIONED → PAY_PER_REQUEST
- **File**: `backend/lib/dictionary-db-stack.ts`
- Changed the table and all GSI billing to `BillingMode.PAY_PER_REQUEST`.
- **Why**:
  - The previous setup used `BillingMode.PROVISIONED` with only 1 RCU and 1 WCU — this is too low for even minimal traffic and would cause throttling.
  - For a dictionary app with sporadic/unpredictable traffic, `PAY_PER_REQUEST` is more cost-effective (no idle capacity charges) and scales automatically without throttling.
  - GSIs no longer require their own billing mode specification when the parent table uses `PAY_PER_REQUEST`.

### Suggestions for Further DynamoDB Improvements
1. **Point-in-Time Recovery (PITR)**: Enable `pointInTimeRecovery: true` on the table to allow recovery from accidental data loss.
2. **GSI Optimization**: The `definition` GSI currently supports exact-match queries but not `contains()` — the `searchEntries` function uses `Scan` with a filter expression. For better search performance, consider integrating **Amazon OpenSearch Service** (formerly Elasticsearch) to provide full-text search, which would replace the expensive `Scan` operations.
3. **Caching with DAX**: For a high-traffic read-heavy workload, **DynamoDB Accelerator (DAX)** can reduce read latency to microseconds and reduce DynamoDB costs.
4. **TTL for Audit Logs**: If you add an audit log or change history table, enable TTL to auto-expire old records.

## 5. Other AWS Service Suggestions

### API Gateway
- The current CORS configuration returns `'Access-Control-Allow-Origin': '*'` (wildcard). Consider restricting this to the actual CloudFront domain (`https://dicionariowapichana.org`) to prevent cross-origin abuse.
- Consider enabling **API Gateway caching** for the read-only `GET /entries` endpoints to reduce Lambda invocations and DynamoDB costs.
- Consider migrating from **REST API** to **HTTP API** (API Gateway v2) for lower cost and latency — HTTP APIs are ~70% cheaper than REST APIs for basic use cases.

### Lambda
- **Cold Start Optimization**: Lambda functions are currently bundled with webpack. Consider enabling **Lambda SnapStart** (for Java) or, since these are Node.js, using **provisioned concurrency** for the authorizer to reduce cold start latency on auth-critical requests.
- **Environment Variables**: The `BUCKET_NAME` is injected via environment variable (good practice). Consider similarly externalizing the DynamoDB table name instead of hardcoding `'wapichana-dictionary'` in the lambda code.

### CloudFront
- The current CloudFront distribution uses `CloudFrontWebDistribution` (legacy L2 construct). Consider migrating to the newer `Distribution` construct from `aws-cdk-lib/aws-cloudfront` for better flexibility, HTTP/3 support, and security headers via `ResponseHeadersPolicy`.
- Consider adding a **CloudFront Function** or **Lambda@Edge** to inject security headers (CSP, HSTS, X-Frame-Options) at the edge.

### Cognito
- The current `CognitoStack` uses L1 (`Cfn*`) constructs directly. Consider migrating to L2 constructs (`UserPool`, `UserPoolClient`) from `aws-cdk-lib/aws-cognito` for better type safety and CDK-managed defaults.
- Consider enabling **MFA** (`mfaConfiguration: 'OPTIONAL'`) to improve security for editors.
- The `FederatedPrincipal` for the editor role is missing `'sts:AssumeRoleWithWebIdentity'` as the `sessionTags` condition — add this to follow AWS best practices.

### S3
- The media bucket (`wapichana-bucket`) should have **versioning enabled** to protect against accidental file deletion.
- Consider enabling **S3 Intelligent-Tiering** for media files that are infrequently accessed to reduce storage costs.
- Review CORS configuration on the media bucket to ensure it only allows requests from the CloudFront distribution domain.

## 6. UI Improvements

### Removed Deprecated `serviceWorker` Import
- The `serviceWorker.js` import in `src/index.tsx` was removed as it is no longer relevant with the updated React 18 setup (it was a CRA legacy artifact that only unregistered service workers).

### Improved Error Messages in Auth Flow
- `Authenticator.tsx`: Added handling for `NotAuthorizedException` (Amplify v6 uses different error codes than v3) to show the correct "Email ou senha incorretos" message.

### Suggested UI Improvements
1. **Loading State**: The global `loading` spinner in `App.tsx` is displayed for all async actions. Consider more granular loading states per component (e.g., a skeleton loader on the word list).
2. **Responsive Search**: The `Search` component's language selector disappears on mobile. Consider making it a toggle or dropdown to improve the mobile UX.
3. **Empty State**: When a letter has no entries, show a friendly empty-state message instead of an empty list.
4. **Accessibility**:
   - Add `aria-label` to icon-only buttons (`Edit`, `ArrowBack`, `Menu`, `DeleteForever`) for screen reader support.
   - The `<text-input>` web component used in `WordEditor` uses `contentEditable` — consider replacing it with standard `<textarea>` for better accessibility and browser compatibility.
5. **Word Editor UX**: The editing experience uses `contentEditable` divs via a custom web component. Replacing this with controlled `<TextField>` components (MUI) would provide better form validation, undo/redo support, and screen reader compatibility.
6. **Toast Positioning**: Consider configuring `<ToastContainer position="bottom-right" />` to avoid toasts overlapping with the header navigation.
7. **Dark Mode**: Add a dark mode toggle using MUI's theme switching capability for improved user comfort.
